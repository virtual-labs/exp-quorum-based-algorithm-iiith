🔒 Maekawa's Quorum-Based Mutual Exclusion - User Guide

🎯 Overview

This simulation demonstrates Maekawa's algorithm for distributed mutual exclusion using quorum-based voting. Each participant must obtain votes from its quorum set before accessing the critical section.

🖱️ Interactive Controls

🔧 Network Configuration:
  • Participants Slider: Adjust the number of nodes (4-16)
  • Quorum Size: Automatically calculated as √n
  • Animation Speed: Control simulation speed (0.25x - 3x)
🔐 Critical Section Controls:
  • Request CS Access: Selected participant requests critical section
  • Release CS: Current owner releases critical section
  • Reset System: Reset all participants to initial state
  • Participant Selector: Choose which node requests access
⚠️ Deadlock Management:
  • Simulate Deadlock: Create multiple simultaneous requests
  • Resolve Deadlock: Use timestamp-based resolution
💥 Failure Scenarios:
  • Random Node Failure: Simulate participant failure
  • Recover All Nodes: Restore failed participants
  • Click Failed Nodes: Manually recover individual nodes

🎨 Visual Legend

Available Node: Ready to participate in voting
Requesting CS: Sending requests to quorum members
Voting: Processing vote request from another node
In Critical Section: Currently accessing shared resource
Failed Node: Unavailable for voting or requests
Locked/Waiting: Involved in deadlock scenario

🔄 Algorithm Process

1
Request Phase: Participant sends REQUEST messages to all members in its quorum set
2
Voting Phase: Quorum members vote YES if they haven't voted for someone else, NO otherwise
3
Access Decision: If all quorum members vote YES, participant enters critical section
4
Release Phase: After completion, participant sends RELEASE messages to quorum members

🎓 Educational Notes

Quorum Properties: Each quorum set has size √n and any two quorum sets intersect in at least one node, ensuring mutual exclusion.

Deadlock Prevention: Maekawa's algorithm can experience deadlocks when multiple requests occur simultaneously. The simulation uses timestamp-based ordering for resolution.

Fault Tolerance: Node failures can prevent quorum formation. The algorithm gracefully handles failures but may need manual recovery.

Message Complexity: Each request requires 2√n messages (request + release), making it more efficient than other distributed algorithms.
